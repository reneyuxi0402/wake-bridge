# wake-bridge 0.9.0-preview.19

本版仅改进 wake payload 的精确批量读取性能，并收紧跨平台发布门禁；不扩大宿主支持承诺。

## 精确批量读取

- 按 batch 引用的精确 Claim / Event ID 集合，以两次 SQLite 查询构建 payload，减少逐条读取启动 `sqlite3` 子进程的开销，不依赖有页数上限的历史索引。
- 保持 Claim 顺序、重复引用、note、instance 隔离与非 batched Claim 过滤；缺失或无状态 Event 的回退语义不变。
- Event 查询只读取 payload 引用所需的 `id`、`source`、`type`，避免无用 metadata / preview 占用子进程 JSON 输出预算。

## 发布门禁

同一 tag commit 必须在 macOS / Ubuntu 24.04 × Node 20 / 24 四组 CI 上全部成功，才运行打包与发布 job。
任一失败或取消都会阻止发布，不依赖另一次 main CI 的完成时序。该门禁是 preview.18 发布后的修复；已发布的 preview.18 tag 与 tarball 保持不变。

## 验证范围

发布前本地回归共 409 项测试通过（392 项 Vitest + 17 项 Claude adapter Node 测试），包含精确批量读取与仓库外 tarball 安装黑盒验证。
四组 CI 均已有通过记录；macOS Node 20 首轮停滞后取消，重跑通过，原因尚未确定。
这些记录不等于本版真实 tag 发布门禁已验收，发布时仍须在同一 tag commit 上重新通过四组 CI。
本轮没有新增真实模型端到端 UAT，既有现场证据与限制仍以各 adapter 验证文档为准。

## 升级与兼容性

发布后可显式安装：`npm install --global wake-bridge@0.9.0-preview.19`。
升级前按 [release lifecycle](../operations/release-lifecycle.md) 备份并核对运行中的 package/config/service 路径；本次发布不自动升级或重启任何现有实例。

- DB schema 仍为 8，没有新增迁移；公开契约和已有策略、来源启用状态不变。
- 从更早版本升级时，仍须阅读 [preview.18 升级说明](0.9.0-preview.18.md) 与其中引用的既有要求。
