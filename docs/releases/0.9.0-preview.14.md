# wake-bridge 0.9.0-preview.14

This preview fixes storage integrity and scale problems found in a production Agent Space after about a month of retained history, and adds an operator-invoked retention command. No schema migration is required.

## Scheduling past 1000 retained claims

- Every listing read `ORDER BY created_at ASC LIMIT 1000`. Once an Agent Space retained more than 1000 claims, `tick()` stopped seeing new ones, so new work was never batched or delivered and nothing reported an error. The scheduler now selects pending, deferred and eligible claims in SQL, whatever the size of the history.
- The same first-page truncation is removed from dismiss/consume, event-to-claim lookups, source-filtered claim lists, the emit merge lookup and the open-batch sweeps. Past 1000 batches, dismissing or consuming a claim could leave it in its open batch, which later dispatched empty into `needs_attention`.
- `attention_status` counts claims and batches in SQL instead of over the first page.

## Atomic transactions

- The sqlite3 CLI keeps executing after a failing statement and still reaches `COMMIT`, so a transaction that raised an error could leave part of its writes committed. Every connection now runs with `.bail on`: a failing statement rolls back the whole transaction. Schema migrations are covered as well.
- The visible symptom: when two writers raced on the same event dedupe key, the losing write could append a nonexistent event id to an existing claim.

## List surfaces show current state

- `attention_list`, `attention_event_list` without `after`, owner HTTP `GET /v1/events|claims|batches|receipts` and CLI `events|claims|batches|receipts` return the newest `limit` rows, still oldest first. Output is unchanged while a table is under the limit.
- HTTP `/v1/claims` and `/v1/batches` accept `?limit=` (1–100000). A non-numeric limit returns 400 instead of 500.

## Acknowledgement timeouts close once handled

- An `ack_timeout` batch whose claims are all consumed, dismissed or expired now moves to `cancelled` (transition reason `all_claims_finalized_reconciled`, `last_error` kept as `ack_timeout`). It still spends at least one sweep in `needs_attention` and raises a configured core incident; a claim that can still be delivered keeps it open.

## Retention

- `wakebridge prune --older-than-days N [--apply]` removes finished delivery history: `seen`/`cancelled` batches that carry no deliverable claim, with their transitions, attempts, receipts and delivery correlations, and consumed/dismissed/expired claims that no surviving batch references, with their transitions.
- Without `--apply` it only reports counts. Nothing runs it automatically; history is still kept by default.
- Events, event status and transitions, and idempotency keys are never deleted. They are the dedupe record, so a re-delivered source event still returns `duplicate: true` (without a claim) instead of waking the agent again.
- Replaying the idempotency key of a pruned self commitment returns `claim_pruned` (409) instead of `storage_corrupt` (500).

## Other changes

- A consume receipt attaches to the newest batch holding the claim when a snoozed claim was re-batched.
- `listAttempts()` is scoped to the instance.
- Validation constants are shared from one module; no behavior change.
- `WakeBridge.emitEvent` accepts `(source, input)` only, and the unused internal `createMcpServer`, `runMcp` and `jsonValue` are removed. None of these are part of the package exports.

## Verification

- Core/package suite: 141 tests passed on Node 20 and Node 22.
- Claude CLI Host Adapter suite: 17 tests passed.
- New regression tests fail on the previous code and pass on this release: transaction rollback, a lost dedupe race, claims and batches behind 1000 retired rows, list windows over MCP and HTTP, ack-timeout reconciliation and retention.
- Retention was run against a copy of a one-month production Agent Space: a 7-day prune removed 682 batches and 698 claims in 0.33 s and kept all 1442 events, all 46 `needs_attention` batches and every live claim.

## Requirements

- Core now reads claim and batch id arrays with SQLite's JSON1 functions (`json_each`, `json_array_length`), so the SQLite CLI must include JSON1 in addition to `-json` output. JSON1 is built in from SQLite 3.38; the macOS system SQLite and Ubuntu 24.04 (CI) satisfy it, and older CLIs need it compiled in. This requirement was missing from these notes as first published; the next release adds a `json_functions` check to `wakebridge release-preflight`.

## Upgrade notes

- No schema migration is required.
- npm `latest` now points to this release and the `preview` dist-tag has been removed. Install with `npm install --global wake-bridge`.
- Installing does not run retention. After the daemon restarts, the dispatcher's next sweep closes existing acknowledgement timeouts whose claims are all finished.
- MCP server processes that are still running an older package keep listing and counting only the oldest page. Restart them, or the sessions that own them, so they use the same version as the daemon.
