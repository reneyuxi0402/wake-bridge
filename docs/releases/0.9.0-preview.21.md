## 多 Agent 与多 Channel

- 多 agent 复用 package，但每个 Agent Space 仍使用独立 daemon、SQLite、端口与凭据；不是共享多租户服务，channel 不是隔离域。
- 通用 `HostSessionClient.openChannels()` / `leases()` 原子登记同一精确 session 的完整 channel 集合；endpoint/token 共享、generation 逐路独立。旧单 channel API 保持兼容。
- 同 session 重登必须包含仍绑定的全部 channel，否则返回 `409 host_session_channels_required`；重登旋转 token，renew/close 为 endpoint 级，不是单路解绑。一路迁走不停止剩余路。
- MCP 与 owner HTTP 提供 channel create/list/rename/delete，稳定 ID 与显示名分开。默认有效 channel 上限32，由实例配置在1–1024内调整；已有超限数据不裁剪。
- Host manifest 可显式选择 `attention_channels: "*"`，只授权本 Space 已登记的有效 channel，不自动扩展旧 allowlist，也不授权 host 创建或删除 channel。

## 本轮 review 收尾

默认删除检查当前 binding、启用 activity watch、当前启用且受支持 policy 的字面 channel target；使用中返回
`409 channel_in_use` 和安全 `usage`（`binding: null | {endpoint_id,generation}`、`activity_watch: boolean`、`policies: [{id,version}]`）。
Agent MCP 与 owner HTTP 均支持显式严格 boolean `force:true`；省略为 false，字符串/数字/null 不接受。
删除在事务中解除该路 binding/presence/watch 并终止待处理工作，保留历史，不恢复或复用旧 ID，不提供 channel restore。
在途或已交宿主的消息无法追回；后续 ack/consume 收到 `channel_deleted` 为终态，应检查状态并停止盲重试，不把删除记作已消费。

仅来源 emit 的隐式目标额度不足时，事件落盘为 suppressed、reason 为 `channel_limit_reached`，不创建 channel/claim，cursor 继续；
已删目标同理为 `channel_deleted`。显式 create/schedule/watch/host 注册额度不足仍429。
释放额度不自动补发，原 dedupe 重放仍返回原 suppressed 事件。

Operator status 增加 `ingest.channel_suppressions`：两原因 counts、`latest_at` 与至多20条
`event_id/source/matched_policy_id/matched_policy_version/reason/at` 的安全 recent 摘要；MCP
`attention_event_list` / `attention_wake_health.events` 增加 `suppression_reason`（两原因或 null）。
这些基于保留历史而非终身计数，不含 payload，不单独改变 health/attention_required，也不新增 incident。

Reference adapter 在 presence/activity 得到确定 `stale_generation` / `channel_deleted` 时，只移除对应旧 handle 与接收 binding；
迟到错误不影响替代 handle，其他路继续观察、续租和接受。所有路失效后停止续租并拒绝投递，不盲目 close 共享 endpoint。
`endpoint_fenced` 才表示整个 endpoint token 失效；两种情况均不自动 reopen 或 takeover。
SDK 保留兼容 `code`，安全 `remote_code` 提供稳定远端原因，不要求解析任意错误正文。

## Schema 8 → 9 与回退

已发布 preview.20 使用 schema 8，候选使用 schema 9（稳定 channel ID、显示名与删除标记）。
新建实例由 init 创建；已有 schema 6/7/8 必须停止 daemon/service，使用 [显式离线 upgrade](../operations/release-lifecycle.md#显式-upgrade)，
先创建并验证一致性 backup 再迁移。普通 daemon/CLI/MCP 不隐式升级；迁移或验证失败尝试恢复该 verified backup，持续文件系统故障仍可能阻止恢复。
升级回填旧路由，不因新额度裁剪历史数据。

旧 preview.20 不能打开 schema 9。回退必须离线恢复升级前、与旧包兼容的 verified backup，再安装匹配旧包；
不能仅降级二进制，恢复也不能保留备份后新产生的工作。升级、安装和发布均不自动替 operator 重启或改动现有实例。
