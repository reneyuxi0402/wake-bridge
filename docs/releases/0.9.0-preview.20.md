# wake-bridge 0.9.0-preview.20

本版改进安全错误诊断、积压调度边界与维护恢复，并补充安装帮助和 CI 停滞诊断；不扩大宿主或平台支持范围。

## 安全错误诊断

- SQLite 失败统一为固定分类：`database_unavailable`、`database_output_limit`、`database_execution_failed`、`database_invalid_json`，不在异常中保留原始 SQL、进程输出或 cause。
- daemon 的 scheduler / adapter cleanup warning 记录固定 `phase` 与 `error_class`；未分类内部错误另带本地白名单 `error_type`（如 `TypeError`、`Error` 或 `unknown`），不读取任意异常的 name、message 或 stack。
- 非契约 HTTP 异常返回固定 500 文案、`code=internal_error` 与安全 `error_class`，不增加 `error_type`；既有 SDK 契约校验保留 status/code 与提示。配置解析及 connector 网络错误也避免透传原始异常。
- scheduler 失败后 daemon 保持运行、后续轮次继续尝试；HTTP 存活不代表调度或投递成功。这不是任意第三方 adapter 日志的自动脱敏承诺，诊断步骤见 [operator control](../operations/operator-control.md)。

## Source 有效配置解释

`source-validate` 增加 `enabled_semantics`；live source status 增加 `loaded_config_enabled`、`persisted_control_enabled` 与 `enabled_source`，区分启动时加载的配置初值和持久 enable/disable 控制。
行为不变：省略 `enabled` 仍默认 true，示例配置显式关闭，持久控制优先；修改磁盘文件不等于修改当前运行值。离线 status 的新增解释字段为 null，不代表 false。详见 [source connectors](../operations/source-connectors.md#有效配置为什么与文件不同)。

## 积压调度边界

- 在 SQLite 中预筛到期/过期 Claim 和到期 Batch，避免先把大量未来工作及无关字段读入进程；事件合并仍要求来源、resource 结构与投递策略语义相同。
- 每次 `tick()` 至多推进 1000 条到期/过期 Claim，再至多将 1000 条 eligible Claim 编批；按当前合批键定位可追加 Batch。
- 每次 `dispatchDue()` 至多检查 1000 个到期 Batch，在 Batch 之间用单调运行时钟检查一秒软预算，至少允许一个候选推进；预算耗尽后让出事件循环，余量留给后续轮次。优先有有效 binding/endpoint 的 channel，等待项通过既有时间戳轮转；投递前仍重查时间门、binding、generation 与 lease。

一秒预算不是 timeout 或硬延迟保证：它不能打断 recovery、同步 SQL 或在途 transport，也不限制 tick 阶段。并非全部查询都已分页；恢复扫描、大范围 inspect 与单个超大记录仍有成本和输出容量边界。

## 恢复、安装与 CI

- restore 复制失败时也清理可能留下的部分临时文件；补充备份敏感性、长期维护与隔离恢复演练说明。坏原库应先保全，再恢复到独立目录，不绕过完整性校验。故障回归使用一次性 ENOSPC 注入，不代表真实磁盘耗尽或持续文件系统故障下的恢复保证，见 [维护 runbook](../operations/release-lifecycle.md#长期维护与隔离恢复演练)。
- 已安装 reference adapter 的帮助明确 package 工作目录、空闲 loopback 端口、channel 一致性及首次测试事件；stdout envelope / `transport_accepted` 只证明协议 wiring，不代表真实 agent 已处理。
- macOS Node 20 CI 增加有界停滞诊断、进程/调用栈证据及短期 artifact；不把诊断采集当作既有停滞根因已确认。

源码提交 `c281df1` 的本地回归共 505 项通过（488 项 Vitest + 17 项 Claude adapter Node 测试）；[CI 40284178626](https://github.com/reneyuxi0402/wake-bridge/actions/runs/40284178626) attempt 1 的 macOS / Ubuntu 24.04 × Node 20 / 24 四组全部通过。

发布仍须在同一 tag commit 上重新通过四组 CI，之后自动将打包产物发布到 npm `latest`，并创建附 tarball 与 SHA-256 清单的 GitHub pre-release；任一失败或取消都会阻止发布。

## 升级与兼容性

发布后可显式安装：`npm install --global wake-bridge@0.9.0-preview.20`。
升级前按 [release lifecycle](../operations/release-lifecycle.md) 备份并核对 package/config/service 路径；本次发布不自动升级、重启或改动任何现有实例。

- DB schema 仍为 8，无新增迁移；依赖与运行时前提不变。
- 既有配置、策略、source 启停及持久状态不变；新增解释字段不改变默认行为。
- 不扩大支持或验证承诺；从更早版本升级仍须阅读 [preview.18 升级说明](0.9.0-preview.18.md) 及其中引用的要求。
