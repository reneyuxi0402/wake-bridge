# wake-bridge 0.9.0-preview.10

版本日期：2026-09-21。发布通道：preview。

## 目标

为已接受但长期未收到 agent acknowledgement 的投递提供可审计的 operator 处置状态，不改变 Event/Claim/Batch、
SQLite schema（schema 8）或 Host Adapter Contract。

## 变更

- 默认确认超时为 30 分钟，从当前 accepted attempt 的 `finished_at` 起算，而不是事件发生、开始投递或最近一次状态变更；
  可用实例配置 `ack_timeout_ms` 或 `WAKEBRIDGE_ACK_TIMEOUT_MS` 设置正整数毫秒值，环境变量优先。
- Canonical dispatcher 在恢复/调度扫描时将超时的 `dispatched` batch 标记为 `needs_attention`，原因
  `ack_timeout`，并保留状态转换记录；只读 observer 不推进此状态。
- `needs_attention` / `ack_timeout` 不自动重投，不修改 Claim/Event，不伪造 `agent_seen` 或
  `agent_consumed` receipt。宿主可能已经收到消息，operator 应先核对真实结果。
- 原 accepted attempt 的合法迟到 ack 仍可转为 `seen`；endpoint、generation 与 attempt fencing 保持不变，
  旧代 binding 不能确认新代投递。
- 不需要 schema migration。升级后，历史上已 accepted 且超过时限的 batch 进入需要处理状态是预期行为，不代表重复投递。
