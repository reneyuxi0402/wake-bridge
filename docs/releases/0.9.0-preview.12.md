# wake-bridge 0.9.0-preview.12

This preview strengthens delivery evidence, self-commitment handoff, scheduling diagnostics, duplicate claim handling, and optional core incident reporting.

## Host-attested delivery

- A Host Adapter can echo the current delivery attempt's one-shot nonce to record `host_attested` evidence and close that batch as `seen`.
- A later explicit agent acknowledgement can still add `agent_seen`; host evidence never claims that the agent understood or acted on the wake.
- A valid echo can outrank a lost transport response and prevent unnecessary redelivery, while arbitrary batch acknowledgement remains rejected.

## Claim payload and scheduling

- Wake payloads include the original note only for `self_commitment` claims, so an agent can recover why it scheduled its own wake without exposing notes from other origins.
- Scheduling without a current attention-channel binding now returns an advisory `no_current_binding` warning. The commitment remains durable and can be delivered once a binding exists.

## Duplicate claim consolidation

- Compatible, unfrozen claims for the same source, resource, and attention channel are consolidated before delivery while preserving every underlying event.
- Claims with incompatible delivery or batching semantics, and claims that have already frozen into delivery, remain separate.

## Optional core incidents

- Operators may set `incident_attention_channel` or `WAKEBRIDGE_INCIDENT_ATTENTION_CHANNEL` to project deduplicated `wakebridge.core` incidents for acknowledgement timeouts and Source Connector `needs_attention` states.
- Core incident projection is disabled by default, cannot mask the authoritative failure, and suppresses recursive incidents about its own acknowledgement timeout.

## Upgrade notes

- No schema migration is required for this preview.
- Existing deployments keep their current behavior unless the optional core incident channel is configured.
- Publishing this package does not upgrade or restart existing Wake Bridge installations.
